# M3 Drifter Skill Content

This document fills the shared P1-P18/A1-A6 advancement slots with a distinct
concept for each Drifter. It is authored content direction for M3, not a balance
sheet. The shared slot purposes, level gates, costs, and stat identities are
defined in [M3 Character Advancement](m3-character-advancement.md) and the
[Universal Advancement Blueprint](m3-advancement-blueprint.md).

## Authoring Contract

- Each Drifter receives one single-purchase passive for each P slot and one
  active skill for each A slot. No multi-rank passive nodes are authored in
  this first set; each passive costs 2 GP.
- Each active costs 3 GP. A1 is a non-mana normal move; A2/A3/A5/A6 are mana
  techniques; A4 is the additional Super. A1 still costs GP.
- The names below are display names. Runtime IDs should be canonical snake-case
  IDs based on the Drifter and slot, such as `branoc_p01` and `branoc_a01`.
- These entries specify combat intent and existing mechanic anchors only.
  Coefficients, damage composition, status timing, mitigation, rounding, and
  unsupported effect mechanics remain subject to Gate 2 and are not implied by
  the prose below.
- Tier gates are sufficient by default. No skill prerequisites or mutually
  exclusive branches are required by this content set.
- A new move joins its owner's permanent available move pool when purchased.
  It does not automatically replace one of the four equipped normal moves.
  The additional Super is tracked outside those four slots.
- The existing authored starting moves and Super remain available to new and
  legacy saves. M3 adds options; it does not turn the starting kit into a
  purchase requirement.

## Gate 2 Authoring Notes

The concepts above intentionally do not assign numbers. Gate 2 must decide which
effects can use existing combat fields and which require a new, narrowly typed
effect. In particular, control/party effects, status-triggered bonuses,
additional Super behavior, mana discounts, and conditional follow-ups need
explicit target, turn, hit/miss, resource, and save ownership semantics before
they are implemented. Do not treat a skill title or flavor sentence as
authorization to invent those semantics silently.
